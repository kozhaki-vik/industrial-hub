# 🚀 Инструкция: Публикация обновлений через GitHub Releases

Эта инструкция описывает актуальную архитектуру системы обновлений **Industrial Hub** и пошаговый процесс выпуска новых версий (как в тестовую ветку **Test**, так и в стабильную ветку **Main**).

---

## ❓ Архитектура системы обновлений

1. **Разделение репозиториев:**
   * 🔒 **Приватный репозиторий (`kozhaki-vik/industrial-hub`):** Содержит исключительно исходный код проекта. Доступен только разработчикам.
   * 🌐 **Публичный репозиторий (`kozhaki-vik/industrial-hub-releases`):** Служит CDN-хранилищем для скомпилированных обновлений (`.exe`). Не содержит исходного кода.

2. **Формат сборки:**
   * Приложение собирается в единый переносимый файл (Standalone Portable `.exe`): `release\Industrial Hub X.X.X.exe`.
   * Архивы `client.zip` и раздача обновлений напрямую с сервера **больше не используются**.

3. **Ветви версий (Channels):**
   * 🧪 **Test (Тестовая):** Релизы на GitHub с отметкой **Pre-release** (`IsPreRelease: true`). Переключение клиентов на ветку Test в приложении защищено PIN-кодом `2136`.
   * 🛡️ **Main (Стабильная):** Обычные релизы на GitHub (**Release**, `IsPreRelease: false`).

4. **Webhooks и мгновенное оповещение:**
   * При публикации релиза в публичном репозитории GitHub отправляет Webhook на сервер `industrial-hub.duckdns.org`.
   * Сервер мгновенно рассылает сигнал всем подключенным клиентам.
   * Клиенты обращаются к GitHub Releases API с защитой от кэширования Fastly CDN (Cache-Buster `?t=${Date.now()}`), скачивают новый `.exe` напрямую в папку `app-X.X.X` рядом со старой версией и запускают её с параметрами автоочистки `--cleanup-pid` и `--cleanup-dir`.

---

## 🔢 Правила версионирования (Semantic Versioning)

Формат версии состоит из 3 чисел, например: **`2.8.1`**:
* **1-я цифра (`2`):** Глобальная версия (Major).
* **2-я цифра (`8`):** Стабильная версия (Main). Увеличивается на `+1` только при выходе официального стабильного релиза (при этом 3-я цифра сбрасывается в `0`, например: с `2.7.92` до `2.8.0`).
* **3-я цифра (`1`):** Тестовая версия (Test). Увеличивается на `+1` при **каждом** изменении/патче (`2.8.1`, `2.8.2`...).

## 🛠️ Пошаговый регламент выпуска обновления

### Шаг 1: Поднятие версии в `package.json`
Откройте `package.json` и увеличьте номер версии:
* Для обычного хотфикса/теста: увеличьте третью цифру на `+1` (например, с `2.8.0` до `2.8.1`).
* Для официального стабильного релиза (только по прямому указанию): увеличьте вторую цифру на `+1`, а третью обнулите (например, с `2.8.9` до `2.9.0`).

### Шаг 2: Фиксация изменений в Git
Перед созданием сборки обязательно сохраните код в приватный репозиторий:
```powershell
git add .
git commit -m "Описание изменений v2.8.1"
git push
```

### Шаг 3: Сборка клиента
Скомпилируйте веб-часть, упакуйте Electron и подпишите `.exe`:
```powershell
# 1. Сборка React фронтенда
npm run build

# 2. Компиляция Electron Portable EXE
npx electron-builder --win

# 3. Подпись цифровым сертификатом Industrial Studio (Kozak)
& "C:\Users\Developer\AppData\Local\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0\windows-10\x64\signtool.exe" sign /sha1 F275C9D48A3325871DB04B0FDFB5701BE34802B7 /fd sha256 /tr http://timestamp.digicert.com /td sha256 "release\Industrial Hub 2.17.0.exe"
```
После успешной сборки готовый подписанный исполняемый файл появится в папке:  
`release\Industrial Hub 2.17.0.exe`

### Шаг 4: Публикация релиза на GitHub

#### Вариант А: Автоматическая публикация через скрипт (РЕКОМЕНДУЕТСЯ)
В корне проекта находится готовый скрипт `upload_release.ps1`. Он автоматически создаёт черновик релиза, загружает 100-МБ файл и публикует релиз:

* **Для тестовой сборки (Pre-release):**
  ```powershell
  & .\upload_release.ps1 -Version "2.8.1" -FilePath "release\Industrial Hub 2.8.1.exe" -IsPreRelease $true
  ```

* **Для стабильной сборки (Main Release):**
  ```powershell
  & .\upload_release.ps1 -Version "2.8.0" -FilePath "release\Industrial Hub 2.8.0.exe" -IsPreRelease $false
  ```

---

#### Вариант Б: Ручная публикация через веб-интерфейс GitHub
Если по какой-то причине скрипт недоступен, публикацию можно выполнить вручную.

> [!CAUTION]
> **КРИТИЧЕСКИ ВАЖНО:** Всегда создавайте релиз как **DRAFT (Черновик)**! Если опубликовать релиз ДО полной загрузки `.exe`, Webhook сработает раньше времени, и пользователи скачают пустой или повреждённый файл.

1. Перейдите в публичный репозиторий релизов:  
   👉 [https://github.com/kozhaki-vik/industrial-hub-releases/releases](https://github.com/kozhaki-vik/industrial-hub-releases/releases)
2. Нажмите **Draft a new release**.
3. **Choose a tag:** Введите `v2.7.8` (с буквой `v` в начале) и нажмите *Create new tag*.
4. **Release title:** Укажите `Industrial Hub v2.7.8`.
5. **Ветка версий:**
   * Для тестовой версии: **ОБЯЗАТЕЛЬНО** поставьте галочку ✅ **Set as a pre-release**.
   * Для стабильной версии: оставьте галочку снятой.
6. **Загрузка файла:** Перетащите файл `release\Industrial Hub 2.7.8.exe` в поле *Attach binaries by dropping them here*.
7. **Дождитесь 100% окончания загрузки файла** (синяя полоса должна исчезнуть, файл должен отобразиться в списке ассетов).
8. Нажмите зеленую кнопку **Publish release**.

---

## 🔍 Как проверить, что обновление успешно доставлено

1. Перейдите по ссылке API (с Cache-Buster):  
   `https://api.github.com/repos/kozhaki-vik/industrial-hub-releases/releases?t=123`
2. Убедитесь, что ваш релиз отображается первым в списке, имеет статус `"draft": false`, и в массиве `assets` присутствует файл `Industrial Hub X.X.X.exe` с размером более 90-100 МБ (`size > 90000000`).
3. Запустите клиент `Industrial Hub` — в течение 5-10 секунд появится уведомление о наличии нового обновления с кнопкой мгновенной установки.
