# 🚀 Инструкция: Как выпустить резервное обновление через GitHub

Эта инструкция написана специально для того, чтобы даже через год вы могли легко вспомнить, как работает система резервных обновлений Industrial Hub и как выложить новый патч.

## ❓ Как работает система
Ваш лаунчер устроен так:
1. Сначала он пытается достучаться до основного сервера (или Cloudflare).
2. Если основной сервер **полностью недоступен** (упал хостинг, заблокировали IP и т.д.), лаунчер автоматически переключается в аварийный режим.
3. Он обращается к GitHub API и ищет последний **Release** (Релиз).
4. Если версия в GitHub Release выше, чем установленная у клиента, он скачивает файл `client.zip` напрямую с серверов GitHub.

---

## 🛠️ Пошаговый план загрузки обновления

Делайте это каждый раз при выходе важного обновления, чтобы у пользователей всегда был рабочий запасной вариант скачивания!

### Шаг 1: Подготовка файла
Соберите обновление как обычно с помощью скрипта `build_full_versions.ps1`.
Убедитесь, что у вас есть готовый файл:
`C:\Users\Developer\Desktop\Проект\[ВЕРСИЯ]\client.zip`
> [!IMPORTANT]  
> Файл **ОБЯЗАТЕЛЬНО** должен называться `client.zip`. Лаунчер ищет именно это название!

### Шаг 2: Создание релиза на GitHub
1. Перейдите в ваш репозиторий: [https://github.com/kozhaki-vik/industrial-hub](https://github.com/kozhaki-vik/industrial-hub)
2. В правой колонке страницы найдите раздел **Releases** и нажмите на него.
3. Нажмите зеленую кнопку **Draft a new release** (Создать новый релиз).

### Шаг 3: Заполнение данных
1. **Choose a tag** (Выбор тега): Нажмите на кнопку и введите версию с буквой `v` в начале. 
   *Пример: `v1.1.25`*
   Затем нажмите синюю подсказку *Create new tag*. (Лаунчер сам поймет и отрежет букву `v`, это нужно просто для порядка в GitHub).
2. **Release title** (Заголовок): Напишите то же самое, например `v1.1.25`.
3. **Описание (опционально)**: Можете написать список изменений, чтобы потом самим помнить, что было в этой версии.

### Шаг 4: Загрузка файла (САМОЕ ВАЖНОЕ)
В самом низу страницы есть большое поле с надписью **Attach binaries by dropping them here**.
Просто перетащите ваш готовый файл `client.zip` в это поле и дождитесь окончания загрузки (появится зеленая галочка или полная полоска загрузки).

### Шаг 5: Публикация
Нажмите большую зеленую кнопку **Publish release**.

---
> [!TIP]  
> **Всё готово!** 
> Теперь, если ваш основной сервер когда-нибудь сломается, лаунчеры всех пользователей автоматически зайдут в этот релиз на GitHub, найдут прикрепленный `client.zip` и успешно обновят программу.
